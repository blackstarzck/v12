# IA, Wireframe, User Flow Analysis Report

작성일: 2026-04-30

분석 대상:

- `docs/IA/*/description.md`
- `docs/IA/*/wireframe.png`

- 참고 비교: `docs/user-flow.md`

## 1. 결론 요약

현재 `docs/IA` 하위 32개 페이지는 모두 `description.md`와 `wireframe.png`를 가지고 있고, 각 페이지의 `Source`, `Code`, 와이어프레임 번호 맵, 화면 목적/분기/피드백/예외 요약도 대체로 일관된 형식으로 작성되어 있다. 와이어프레임도 모두 동일한 캔버스 크기 `1520x1014`로 제작되어 있고, 번호 표기와 `Wireframe Number Map`의 개수도 시각적으로 대응된다.

다만 개발 착수 기준으로는 아직 부족하다. 현재 문서는 "어떤 영역이 화면에 있어야 하는지"는 말해주지만, "어떤 데이터로, 어떤 상태에서, 어떤 전환과 권한으로 동작해야 하는지"가 충분히 계약화되어 있지 않다. 특히 라우트, API/데이터 필드, Ant Design 컴포넌트 매핑, 모바일 반응형 기준, 접근성, 권한/구독 게이트, 상태별 화면 정의가 부족하다.

`docs/flow/user-flow.md`에는 Mermaid 사용자 흐름이 존재한다. 랜딩, 회원가입/로그인, 학습 홈, 문제 선택, 작성, 제출 확인, AI 분석, 피드백, 리포트, 추천, 내 서재, 결제/구독, 관리자 화면까지 주요 IA 페이지를 화살표로 연결하고 있다. 따라서 사용자 흐름이 없다는 판단은 현재 파일 기준으로는 맞지 않다.

다만 흐름 문서와 IA 문서 간 추적성은 아직 완전하지 않다. Mermaid 노드명 중 4개가 `description.md`의 `Source`와 정확히 일치하지 않고, `X03 결제 선택`, `X04 구독 관리`, `X05 프로필 편집`처럼 진입 경로가 약하거나 끊긴 페이지가 있다. 또한 `DM1`, `DM3`, `E02`의 취소/복귀 흐름이 특정 작성 화면으로 고정되어 있어 51/52/53/54번 공통 플로우로 쓰기에는 논리 보강이 필요하다.

우선순위는 다음과 같다.

| 우선순위 | 항목 | 판단 |
| --- | --- | --- |
| P0 | Mermaid 노드명과 `description.md` Source 불일치 수정 | 문서 간 추적 규칙을 깨는 노드가 있음 |
| P0 | 작성/제출/이탈 모달의 복귀 대상 보강 | 공통 모달인데 현재 일부 복귀가 D-04 또는 D-03으로 고정됨 |
| P1 | API/데이터/상태/검증 규칙 보강 | 개발자가 임의 해석해야 하는 영역이 많음 |
| P1 | Ant Design 컴포넌트 매핑 추가 | 프로젝트 UI 정책상 구현 전 필수 |
| P1 | 인증/권한/구독/관리자 역할 기준 정리 | 학습자, 관리자, 기관 관리자, 유료 잠금이 섞여 있음 |
| P2 | 명칭과 논리 불일치 정리 | 일부 페이지명, CTA, 목적, 분기 설명이 어긋남 |

## 3. 전체 구조 점검

### 3.1 잘 되어 있는 부분

- 모든 IA 페이지가 동일한 문서 형식을 갖는다.
- 모든 페이지에 `Source`, `Code`, `Wireframe` 메타가 있다.
- 모든 페이지에 `Wireframe Number Map`이 있고, 와이어프레임에도 대응 번호가 표시되어 있다.
- 주요 화면은 "목적 / 분기 / 피드백 / 예외" 요약을 포함한다.
- 입력 폼, 모달, 목록, 대시보드, 결제, 관리자 화면 등 주요 UI 유형이 폭넓게 분리되어 있다.
- 와이어프레임은 저충실도 기준으로 영역 배치와 우선순위를 파악하기 쉽다.

### 3.2 개발 착수 전에 부족한 공통 항목

아래 항목은 대부분의 페이지에서 빠져 있거나 너무 추상적이다.

| 부족 항목 | 영향 | 보강 방향 |
| --- | --- | --- |
| 라우트와 화면 ID | 개발자가 실제 URL, 진입 조건, 리다이렉트 조건을 추정해야 함 | 각 페이지에 `Route`, `Entry`, `Exit`, `Guard` 추가 |
| 데이터 계약 | 어떤 API 필드와 상태값이 필요한지 불명확 | 주요 UI 영역별 데이터 필드, 타입, 필수 여부, 예시값 추가 |
| 상태 정의 | loading, empty, error, success, disabled가 화면 단위로 통일되지 않음 | 페이지별 상태 표 추가 |
| 액션 결과 | CTA 클릭 후 이동 화면과 실패 처리 기준이 모호 | 액션별 target page/code, 성공/실패 결과 추가 |

| AntD 컴포넌트 매핑 | 프로젝트 정책상 구현 전 필수인데 문서에 없음 | 영역별 AntD 컴포넌트와 주요 props 기록 |
| 반응형 규칙 | "모바일은 접힘/스택" 수준으로만 존재 | desktop/tablet/mobile breakpoint별 레이아웃 명시 |

| 테스트 기준 | 개발 완료 판단 기준이 없음 | 페이지별 acceptance criteria와 QA 시나리오 추가 |
| 분석/추적 이벤트 | 주요 전환 CTA의 측정 기준 없음 | signup, submit, paywall, export 등 이벤트 정의 |

## 4. User Flow 정합성 점검

### 4.1 `docs/flow/user-flow.md` 상태

현재 `docs/flow/user-flow.md`에는 Mermaid 사용자 흐름이 있다. 흐름은 `flowchart TD`로 작성되어 있고, IA 페이지를 노드로 선언한 뒤 CTA/조건 라벨이 붙은 화살표로 화면 전환을 표현한다.

확인 결과:

| 항목 | 결과 |
| --- | --- |
| Mermaid 코드 존재 | 있음 |
| IA 페이지 전체 언급 | 대부분 언급됨 |
| 페이지 간 이동 흐름 | 있음 |
| 모달 발생 조건 | 작성/제출/저장 경고/PDF 흐름 일부 정의 |
| 권한/구독/관리자 분기 | 로그인 성공 관리자, 구독, 기관 관리자 흐름 일부 정의 |
| 완료/오류/복귀 흐름 | 일부 정의되어 있으나 복귀 대상 보강 필요 |

따라서 현재 상태에서는 "사용자 흐름이 없다"고 볼 수 없다. 오히려 핵심 검토 대상은 Mermaid 흐름이 IA 문서의 `Source`와 정확히 맞는지, 각 edge가 실제 UX 전환으로 논리적인지, 공통 모달이 호출 원래 화면으로 정확히 복귀하는지다.

### 4.2 참고 문서 `docs/user-flow.md`와의 차이

루트의 `docs/user-flow.md`에는 레거시 사용자 흐름이 존재하지만, 이 문서는 새 IA 페이지 코드와 직접 연결되어 있지 않다.

예를 들어 루트 문서는 다음 흐름을 포함한다.

- 홈에서 듣기/읽기 문제 생성
- 쓰기 집중 연습 설정
- 쓰기 피드백 확인
- 단어 복습
- 내 서재 복습
- 모의고사
- 게시판
- 프로필과 설정
- AI 튜터

그러나 현재 `docs/IA`의 32개 페이지에는 단어장, 모의고사, 게시판, AI 튜터, 듣기/읽기 문제 생성/풀이 화면이 없고, 반대로 IA에는 페이월, 구독 관리, 약점 기반 추천, 기관 관리자, 관리자 사용자 관리 등이 새로 있다. 따라서 새 흐름의 기준은 `docs/flow/user-flow.md`로 두는 것이 맞다.

### 4.3 Mermaid와 IA Source 대조 결과

현재 Mermaid 노드와 `docs/IA/*/description.md`의 `Source`를 대조하면 아래 4개가 정확히 일치하지 않는다.

| IA Source | Mermaid 현재 노드명 | 판단 |
| --- | --- | --- |
| `09 D-02 52번 답안 작성` | `09 D-02 52번 단답 작성` | IA 문서명을 기준으로 `답안 작성`으로 통일 필요 |
| `20 G-01 설정 언어` | `20 G-01 언어 설정` | 제품 용어를 하나로 확정 필요. 자연어로는 `언어 설정`이 더 적절하나 Source와 불일치 |
| `22 D-M3 자동저장 경고` | `22 D-M3 자동저장 꺼짐 경고` | IA Source 또는 Mermaid 중 하나로 통일 필요 |
| `25 X-03 페이월` | `25 X-03 결제 선택` | 화면 역할을 결제 선택으로 바꿀지, Source를 페이월로 유지할지 결정 필요 |

이 불일치는 화면 자체가 누락됐다는 뜻은 아니다. 다만 `docs/IA/README.md`에서 정한 "Mermaid 페이지명은 `Source`와 일치" 규칙을 깨므로, 구현/QA/문서 추적에서는 오류로 취급하는 것이 좋다.

### 5.3 UX 논리 보강 필요

- 모달은 대부분 배경 dim, 포커스 잠금이 언급되지만 닫기 조건, ESC 처리, 뒤로가기 처리, 모바일 바텀시트 전환 기준이 없다.
- 작성 화면은 자동저장, 제출, 이탈 경고가 중요하지만 상태 전이도가 없다.
- 피드백 화면은 학습 추천과 저장 액션이 있지만 사용자가 "다음에 무엇을 해야 하는지"의 우선순위가 페이지별로 다르다.
- 페이월과 구독 관리에는 결제 실패, 중복 구독, 취소 예약이 언급되지만 결제 제공자/외부 포털/영수증 다운로드 흐름이 없다.
- 관리자 화면은 표/상세 패널 중심인데 감사 로그, 변경 이력, 권한 충돌 처리 방식이 부족하다.

## 9. 개발 착수 가능성 판단

현재 문서는 화면의 큰 구조를 구현하는 데는 참고할 수 있지만, 바로 개발을 시작하기에는 부족하다. 특히 여러 개발자가 병렬로 작업할 경우 라우팅, 데이터, 상태, 권한, 결제, 관리자 역할을 서로 다르게 해석할 가능성이 높다.

권장 판단:

| 영역 | 개발 착수 가능성 | 이유 |
| --- | --- | --- |
| 저충실도 화면 뼈대 | 가능 | 와이어프레임과 영역 설명이 있음 |
| 실제 라우팅 구현 | 부분 가능 | user-flow는 있으나 일부 노드명, 복귀 target, 직접 진입 edge 보강 필요 |
| API 연동 구현 | 보류 | 데이터 계약이 없음 |
| 폼 검증 구현 | 부분 가능 | 일부 글자수/필수값은 있으나 필드별 schema 부족 |
| 결제/구독 구현 | 보류 | provider, 성공/실패/복귀 흐름 부족 |
| 관리자 기능 구현 | 보류 | 권한, audit, 일괄 처리 정책 부족 |
| UI 컴포넌트 구현 | 부분 가능 | AntD 매핑과 반응형 세부 규칙 보강 필요 |

## 10. 최종 권고

이 IA 산출물은 "화면 목록과 화면 영역 설명"으로 유효하고, `docs/flow/user-flow.md`도 실제 Mermaid 사용자 흐름 문서로 볼 수 있다. 다만 제품 구현 문서로 사용하려면 Mermaid 노드명과 `description.md`의 `Source`를 정확히 맞추고, 각 페이지의 `description.md`에 구현 계약을 추가해야 한다.

가장 먼저 해야 할 일은 Mermaid 노드명 불일치 4건을 정리하고, `DM1`/`DM3`/`E02`처럼 호출 원래 화면으로 돌아가야 하는 흐름의 복귀 대상을 보강하는 것이다. 그 다음 각 페이지에 라우트, 데이터, 액션, 상태, AntD 컴포넌트 매핑, acceptance criteria를 추가하면 개발 착수 기준으로 안정화할 수 있다.
